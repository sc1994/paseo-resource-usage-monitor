# 功能与限制

侧栏显示 Paseo daemon 所在主机的 CPU、内存、磁盘和网络速率。点击状态条打开紧凑浮窗，查看主机摘要和排序后的前 5 个进程组；桌面浮窗宽度由宿主限制为最多 420px，手机使用底部抽屉。浮窗展示进程 CPU、内存、下载和上传，可分别排序；浮窗与资源详情共享排序，点击“查看资源详情”进入进程页签。详情网络列默认按双向总量排序，从浮窗带入下载或上传排序时表头注明方向。完整资源页可查看约三分钟的历史、各本地磁盘、运行时间和负载，以及按 CPU、内存、GPU 利用率、GPU 显存或网络排序的前 12 个进程组。主机概览逐卡显示当前 GPU 利用率和显存已用/总量，不平均多卡利用率。宽容器左右排列主机概览和进程，窄容器以页签切换。CPU 的 100% 表示占满一个核心，多核心进程可以超过 100%。

主机指标每两秒采样一次，磁盘每三十秒采样一次；历史保存在内存中，插件重载或 daemon 重启后清空。Linux 主机 CPU 来自 `/proc/stat`，内存使用 `MemAvailable`；macOS 内存参考 `vm_stat` 和系统内存压力。主机网络总量排除回环及常见虚拟接口，本地磁盘按设备去重，不包含网络挂载和只读镜像。

## 进程采样

进程按名称精确聚合（包括不同用户的同名进程），全量聚合后按资源合计排序，再取前 5 组或 12 组。多成员组默认折叠，展开可查看全部成员，释放仅针对单个 PID；单成员直接显示。浮窗摘要和折叠组行在默认字号下保持稳定尺寸，放大字体时允许内容增高，实时数值和排序仍随采样更新。`≥` 表示部分成员有缺测，显示已知值之和；全部缺测显示 `--`，零值保留。组网络总量要求下载和上传均有已知值；任一方向全部缺测时总量显示 `--`，方向细分仍显示已知值。进程表使用紧凑行布局；展开“采集说明”可查看采样限制和受限进程的完整原因。`--` 表示数据缺测。进程内存显示 RSS，可能包含共享页，各进程 RSS 之和不等于主机已用内存。

进程 CPU 采样依赖 Linux `/proc`，按进程 PID 和启动时间比较两次计数；首帧和新进程没有基线时显示 `--`。NVIDIA 指标需要 `nvidia-smi`：进程 SM 利用率与显存分别采集和排序，一个不可用不影响另一个；多个设备的同一进程数值相加。主机整卡利用率不作为进程利用率，显存也不冒充利用率；无数字时显示 `--`。

进程网络需要 `ss`。它只统计可唯一归属的可见 TCP 持续连接，包含回环连接；发送量使用 `bytes_sent`。UDP、无法归属的连接以及两次采样之间结束的短连接不在统计范围内，因此不能与排除回环的主机网络总量直接比较。连接和进程首次出现时没有速率基线。

详情中的网络上下行分项会在本列换行，并保留完整数值。

## 结束与隐私

仅允许请求结束当前用户的进程，PID 1、插件进程及其祖先进程受到保护。确认后仅发送 `SIGTERM`；不会自动发送 `SIGKILL`。结束功能需要 Python 3 的 `os.pidfd_open`、`signal.pidfd_send_signal` 及系统 pidfd 支持，并在打开 pidfd 后重新核对进程启动身份和 UID，避免 PID 复用造成误杀。进程没有及时退出时会报告仍在运行。

进程命令会隐藏常见 password、token、api-key、secret 等参数值及 URL 凭据，但不能保证识别所有自定义敏感参数；插件不读取进程环境变量或凭据文件。主机与进程信息均展示给已连接 daemon 的客户端，包括远程客户端，请按此控制连接权限。插件不连接外部服务。
