# Host monitor 交互设计稿

上游项目：https://github.com/a31521424/paseo-kit，插件目录为 `plugins/host-monitor`。本地复制基线为 `14e6ac03d78c7430c054894557062426acd3f2e9`，用户 fork 为 https://github.com/sc1994/paseo-resource-usage-monitor。原项目 Apache-2.0 许可证及 NOTICE 保持不变。

直接打开 `index.html` 即可预览，无外部依赖。所有数据均为示例，页面不会采样主机、发送请求或操作真实进程；以下内容描述设计稿，而非实时插件。

预览默认打开状态条上方的紧凑浮窗；点击状态条可开关浮窗，“查看资源详情”进入完整页面，“返回浮窗预览”返回，浏览器前进和后退也可切换。浮窗与详情共享示例进程和排序。此交互为浏览器设计稿；正式插件已接入原生浮窗，详情页使用宿主返回导航。浮窗按 CPU、内存、下载或上传排序；详情的 GPU 利用率与显存分别排序，网络默认按双向合计排序，从浮窗带入的下载或上传排序在详情表头注明方向。CPU 100% 代表一个核心。不可用数据始终排在最后，同值按 PID 排序。GPU 或网络不可用时，进程区说明原因并禁用对应排序，CPU 仍可排序。预览状态选择器可查看采集和释放异常。

进程表采用紧凑行布局；“采集说明”默认收起，展开后查看缺测说明和保护原因。内存示例为 RSS，可能包含共享页，各进程之和不等于主机已用内存。

“释放”表示结束进程，可能中断任务并丢失未保存数据；示例仅模拟操作。守护进程受保护，不能释放。确认框支持取消、Esc 和失败重试；示例进程已退出时移除该行，提示无需重复结束。浏览器控制台可运行 `hostMonitorSelfCheck()`，检查升降序、内存和显存零值及缺测排序与受保护进程；断言失败会抛错。

实际实现必须校验操作权限和进程身份，避免 PID 重用导致误杀；GPU 信息受驱动及平台能力限制，进程网络归因也依赖平台和权限，不保证所有环境均可采集。

正式插件实现及使用说明见 [plugins/host-monitor](../../plugins/host-monitor/README.md)。正式浮窗遵循宿主 420px 宽度上限，手机使用底部抽屉；本目录 HTML 仍仅为示例，不操作系统。
